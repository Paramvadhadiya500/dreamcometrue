## 2026-11-20 - Home page: smarter polling (60 s when nothing is live, backoff with jitter after errors)
- **What:** new `public/js/home-logic.js` (pure logic, loaded by the page and tested by `test.js`, built like `queue.js`): `nextDelay(failures, anyLive, random)`: after a good answer 10 s if a match is live, 60 s if not; after errors 10, 20, 40, then 60 s at most; every wait +-20 % random spread. `public/index.html`: the fixed 10 s `setInterval` is replaced by one `setTimeout` planned after each answer (`schedule()`); `failures` counts errors in a row (reset by one success); a hidden tab sends nothing but keeps planning; the `online` event (network back) refreshes at once. `test.js`: `nextDelay` tests. New `e2e/home-polling.spec.js` (5 tests with a fake `/api/home` and Playwright's fake clock). Phase 4, step 4 of the student-pages plan, done first (commit A of Phase 4; by Claude without questions, at the user's request).
- **Why:** before, every phone asked every 10 s even when nothing was live (6 times more requests than needed), and kept asking every 10 s, all in the same rhythm, while the server was in trouble. Now a struggling server gets fewer requests, spread out; a phone whose network comes back does not wait.
- **Trade-off:** with nothing live, a match that STARTS shows as live up to about 72 s later on an open home page (before: up to 10 s). Opening or returning to the page refreshes at once; the match page itself is unchanged (live push).
- **Found while doing it:** my first version planned nothing while the tab was hidden and relied on `visibilitychange` to restart; the old `setInterval` recovered even when that event never comes (it can be missed on some phones after a pause). Changed so a hidden tab keeps planning; the new E2E test FAILS on my first version (`no request within 13000 ms`). Also my first E2E test measured waits from the wrong moment (would have failed a correct page by bad luck); it now counts requests inside the page and moves fake time in 1 s steps.
- **Checked:** the new E2E tests FAIL on the old page (`wait 10000 ms, expected about 60000`, same for errors and `online`; the "live: 10 s" test passes on both, as it should). Breaks of `nextDelay`: no backoff -> unit test and E2E fail; no jitter -> unit test fails (the E2E checks ranges, so it cannot see this); restored byte for byte. Polling tests 5 times in a row: 25 passed. `npm run test:e2e`: 19 passed. `node test.js`: All tests passed (one wrong expected value in my own new test was fixed first: 11999.6 rounds to 12000). NOT checked: a real phone, the server.
- **Undo:** `git revert <this commit>`, then the normal deploy (`docker compose build`, `docker compose up -d`).
